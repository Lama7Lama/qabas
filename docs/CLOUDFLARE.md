# قبس على Cloudflare Pages

الموقع متاح للتجربة دون اسم مستخدم أو كلمة مرور. يضبط `QABAS_ACCESS_MODE=public` الوصول العام، بينما يبقى مفتاح النموذج في الخادم. فتح الوصول لا يغير حالات اعتماد المحتوى أو معايير الفهم في `build:release`.

المشروع الحالي `qabas` يستخدم Direct Upload عبر Wrangler؛ GitHub يحفظ المصدر المفحوص، والنشر ليس تلقائيا عند الدفع. `npm run deploy:cloudflare` يعيد البناء والفحص، ويجهز نسخة مطابقة للبصمات ثم يرفعها فقط. ربط Git تلقائيا لاحقا يحتاج مشروع Pages جديدا، لأن نوع Direct Upload لا يتحول داخل المشروع نفسه. [توثيق Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/).

## الملفات التي ترفع

`npm run prepare:github` يجهز مصدر GitHub بقائمة محددة في `work/github-publish/`، وجرده وبصماته في `work/github-publish-manifest.json`. يفحص الملفات مقابل المفاتيح المحلية وأنماط الأسرار، ويستبعد تاريخ Git وملفات البيئة وبيانات المشاركين ومجلد work والعرض والوثائق الخاصة والأرشيف والخط الخاص والتقارير القديمة.

ملفات الاستضافة في `dist/cloudflare/` فقط: الواجهة، بيانات المواقف المنقحة، الشعار وخط Tajawal بترخيص OFL، والخادم المجمع `_worker.js` وملف التوجيه. لا توجد خرائط مصدر أو مفاتيح أو ملفات اعتماد خاصة في الناتج. لا ترفعي مجلد المشروع كله إلى الاستضافة.

## إعداد Pages من GitHub

1. أنشئي مستودعا خاصا باسم qabas مع README أولي. ارفعي النسخة المفحوصة فقط، دون `.env.local`.
2. في Cloudflare، أنشئي مشروع Pages من المستودع. Framework preset: None. أمر البناء `npm run build:cloudflare`، مجلد الناتج `dist/cloudflare`، وNode.js إصدار 24 أو 22. ملف `wrangler.jsonc` لا يحتوي قيما سرية.
3. في Settings ثم Variables and Secrets، أضيفي **GROQ_API_KEY** كـSecret مع Encrypt. ضعي المتغير غير السري **QABAS_ACCESS_MODE=public** لإتاحة الموقع دون بيانات دخول. لا حاجة لمفتاح Gemini أو قاعدة بيانات. لا تضعي المفتاح في vars أو الشيفرة أو أوامر الطرفية أو المحادثة.
4. أضيفي المتغير غير السري **QABAS_PUBLIC_ORIGIN** بقيمة رابط المشروع الفعلي مثل `https://your-project.pages.dev`، دون مسار أو شرطة نهائية. نطاق معاينة مختلف يرفض الطلب حتى تضبط قيمة بيئته. لا تضيفي QABAS_LOCAL_PREVIEW إلى الاستضافة.
5. اضبطي تجاوز حصة Functions على **Fail closed / Block**، وتحققي من الإعداد في الحساب، حتى لا يقدم الموقع مسارا يتجاوز فحوص الخادم إذا تعطلت الوظائف.
6. أعيدي النشر بعد حفظ الإعدادات. يكفي المفتاح في Production إذا لم تحتاجي المعالجة في Preview. لا تفعلي الدفع تلقائيا.

Pages Functions يعمل بالوضع المتقدم `_worker.js`. النشر عبر ربط GitHub أو Wrangler؛ لا تعتمدي على السحب إلى لوحة التحكم لتشغيل الخادم. [توثيق الوضع المتقدم](https://developers.cloudflare.com/pages/functions/advanced-mode/)، [توثيق Secrets](https://developers.cloudflare.com/pages/functions/bindings/).

## التحقق قبل مشاركة الرابط

`/healthz` يرد بحالة عامة فقط. الصفحة و`/api/config` متاحان دون مصادقة في وضع public. إعداد النموذج لا يكشف المفتاح. جربي رحلة كاملة من الجوال والمتصفح، وتحققي من استجابة Groq الفعلية؛ المحاكاة لا تثبت جودة النموذج. لا توجد بيانات دخول للمستفيدين.

الخادم يتحقق من HTTPS ومصدر الطلب والرؤوس وبنية البيانات، ويقيد الجسم إلى 8192 بايت و15 ثانية للقراءة. يحافظ على مخطط JSON والاقتباس الحرفي والقراءتين من النموذج نفسه، دون إعادة تلقائية أو تحويل خفي إلى مزود آخر. عدادات 12 طلبا في الدقيقة وطلب نشط واحد تعمل لكل isolate، وليست حدا عالميا عبر شبكة Cloudflare.

الخطة المجانية محدودة بالطلبات وCPU. انتظار Groq لا يحسب ضمن CPU، لكن إعداد المخطط وفحص الرد يحسبان. يجب قياس التشغيل الفعلي بعد النشر؛ لا يثبت الفحص المحلي استيفاء حصة CPU. [حدود Cloudflare](https://developers.cloudflare.com/workers/platform/limits/).

يمكن تشغيل مراجعة خاصة عند الحاجة بإزالة وضع public وإضافة QABAS_REVIEW_PASSWORD كسر مشفر بطول 20–200 محرف. هذا الوضع اختياري، وليس إعداد الموقع المنشور الحالي.

## المعاينة المحلية

```sh
npm ci --ignore-scripts
npm test
npm run build:cloudflare
npm run check:cloudflare
npm run dev:cloudflare
```

للمعاينة فقط، ضعي في ملف `.dev.vars` المستثنى من Git `QABAS_LOCAL_PREVIEW=1` و`QABAS_PUBLIC_ORIGIN=http://127.0.0.1:8788` و`QABAS_ACCESS_MODE=public`. اتركي GROQ_API_KEY فارغا للتحقق دون استدعاء النموذج. لا تنشري هذا الملف؛ الاستضافة تستخدم Secrets الخاصة بها.

## الخصوصية

المفتاح في ذاكرة الخادم، والنصوص تمر عبر Cloudflare إلى Groq؛ أضيف هذا الإفصاح إلى «عن قبس» في بناء Cloudflare. لا تنشئ الشيفرة قاعدة بيانات ولا تسجل نص الإجابات أو سمات المستخدم. هذا لا يؤكد احتفاظ المزودين؛ إعداداتهما تحتاج مراجعة في الحساب. لا يضاف Analytics أو KV أو D1 للمشروع.
